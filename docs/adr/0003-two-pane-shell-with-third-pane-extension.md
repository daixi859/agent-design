# 布局为两栏骨架，预留第三栏扩展点

Pi Studio 的 app shell 固定为 Sidebar（左）+ Transcript（右）两栏。agent 客户端常见的第三栏（工具详情、文件预览、usage 面板）本阶段不做，但 shell 布局与语义 token 从一开始就按「未来可插入第三栏」设计：主区域用可分割的容器结构，Transcript 不假设自己占据剩余全部宽度，主题 token 中预留 detail-pane 语义组（背景、边框、宽度变量）。

## 考虑过的选项

- **直接做三栏**：当前没有真实内容填满第三栏（只读阶段工具详情以行内卡片呈现），固定空栏只会在视觉上违背极简目标。

## 后果

- 需要第三栏时只增组件、不改 shell 结构与 token 命名。**2026-11 修订（ADR-0018）**：预留的 detail-pane 令牌组（`--bg-detail-pane` / `--detail-pane-width`）因零引用删除——死预留与「相近就合并」相抵触；第三栏落地时按届时档距规则回补，shell 结构不受影响。
- Transcript 内的行内展开卡片（工具调用、diff）是本阶段唯一的详情呈现方式，将来第三栏出现后两者并存：卡片摘要在 Transcript、完整详情进第三栏。
